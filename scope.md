# Project Scope: UnderstandGuard

**Hackathon:** Devpost — Build with AI: Basics (2026)  
**Product Name:** UnderstandGuard  
**Tagline:** *"AI can write the code. UnderstandGuard makes sure you understand the change."*  
**Document Status:** Approved MVP Scope (Sprint 1)  

---

## 1. Executive Summary & Core Objective

UnderstandGuard is a developer accountability tool designed to eliminate **Cognitive Debt**—the dangerous gap where developers merge AI-generated code they cannot explain, verify, or debug. 

Instead of passively generating code summaries that developers ignore, UnderstandGuard conducts an interactive **Reverse Interview** on an AI-generated Git diff. If the developer cannot explain critical logic, UnderstandGuard flags the unverified function, generates a targeted adversarial edge-case test proving the hidden risk, and exports an architectural `COGNITIVE_MAP.md`.

**Core MVP Goal:**  
> *Prove that a reverse-interview + targeted test workflow effectively surfaces cognitive debt and enforces human comprehension in AI-assisted software development.*

---

## 2. In-Scope (MVP Deliverables)

For the *Build with AI: Basics* proof-of-concept, the product executes **one complete, polished workflow end-to-end**:

1. **Diff Input:**
   * Single-file or multi-hunk Git diff ingestion via paste or sample fixture (focused on ≤ 50 lines of critical code).
2. **AST / Diff Analysis:**
   * In-memory diff parsing using `parse-diff` to extract filenames, line numbers, added functions, and modified state logic.
3. **3-Question Reverse Interview:**
   * Automated generation of three line-specific, probing questions targeting edge cases, error states, and async concurrency.
4. **Comprehension Scoring & Risk Assessment:**
   * Interactive input for developer answers.
   * Heuristic scoring engine evaluating technical depth vs. vague non-answers (e.g., *"handles errors gracefully"* vs. exact failure modes).
   * Visual risk badge: **"Safe to Review"** vs. **"High Cognitive Debt – Review Required"**.
5. **Targeted Adversarial Test Generation:**
   * Synthesis of a runnable, focused unit test specifically testing the function/line where the developer demonstrated weak comprehension.
   * Crisp assertion failure preview (e.g., `expect(status).toBe(200) // got 500`).
6. **Artifact Generation:**
   * Exportable `COGNITIVE_MAP.md` containing a Mermaid architecture diagram and human-readable mental model checklist.
7. **Reliability & Demo Safeguards:**
   * Dedicated `/demo` route pre-loaded with an authentic `auth.ts` diff (concurrency & 429 rate-limit flaw).
   * One-click "Reset" button for seamless, repeatable video recording.
   * `?mock=true` deterministic mode to guarantee sub-second latency and zero API failures during presentations.

---

## 3. Explicitly Out-of-Scope (Deferred to Post-Hackathon v2)

To maintain strict hackathon discipline and avoid bloated, half-finished features, the following are intentionally excluded from MVP:

* ❌ **Full GitHub Action / CI/CD Integration:** No automatic PR blocking or GitHub webhook integration.
* ❌ **Full Monorepo Traversal:** No multi-repository dependency graph indexing.
* ❌ **Multi-Language Sandbox Execution:** Tests are rendered with assertion previews rather than running inside dynamic multi-runtime Docker containers.
* ❌ **User Authentication & Enterprise SSO:** No team accounts, billing, or database persistence.
* ❌ **Arbitrary File Generation:** Focused strictly on the diff analysis and `COGNITIVE_MAP.md` output.

---

## 4. Constraints & Assumptions

* **Video Demo Constraint:** The complete end-to-end user journey must execute smoothly within a **2-minute screen recording**.
* **Model Dependency:** Uses Google Gemini API with robust client-side fallback/mock support.
* **Developer Context:** Assumes the developer is reviewing code generated by an AI coding agent (e.g., Cursor, Claude Code, GitHub Copilot).
